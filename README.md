# CoMinVi Webflow Scripts

## Commands

`yarn`  
Installs the project dependencies.

`yarn dev`  
Starts the local Vite dev server. Use it to test the scripts and assets bundled through `src/main.js`.

`yarn build`  
Creates the production bundle in `dist/`, including `dist/main.js`, dynamic chunks, and `dist/manifest.json`.

`yarn preview`  
Serves the generated `dist/` output after a build.

`yarn clean`  
Deletes the `dist/` folder.

`yarn lint:fix`  
Runs ESLint with automatic fixes on `src/**/*.js` and `src/**/*.jsx`.

## Structure

`src/main.js` is the Vite entry point. It initializes the loader, Lenis, navigation, Barba transitions, and the page module registry.

`src/app/` contains shared orchestration logic, especially `page-registry.js`, which dynamically loads animations based on the page Barba namespace.

`src/animation/` contains animation and interaction modules. Files are generally organized by page or component: `technology.js`, `contact.js`, `map.js`, `service-icons.js`, etc.

`src/styles/style.css` contains custom styles injected by `src/main.js`. `src/styles/cominvi-staging.webflow.css` is a copy of the exported Webflow CSS, useful for local adjustments and reference.

Root HTML files (`index.html`, `technology.html`, `contact.html`, etc.) are copies of the Webflow pages. They are used as references and local test fixtures, but Webflow remains the structural source of truth.

`public/` contains static assets served as-is, including videos and local Lottie JSON files. These files are copied into `dist/` during build.

`dist/` is generated by Vite. Do not edit its contents manually.

`reports/`, `docs/`, and `scripts/` contain reports, notes, and one-off verification scripts.

## How It Works

The Webflow site loads the `main.js` bundle produced by Vite. In production, `vite.config.js` uses `base` to publish assets from the configured Netlify URL.

Heavy modules are loaded dynamically per page or on demand. For example, the MapLibre map is isolated in the contact module, and Lottie is loaded through `service-icons.js` only when icons need to be initialized.

Page transitions are handled by Barba. After each transition, `page-registry.js` reruns the required initializers on the active container.

The project uses GSAP, ScrollTrigger, Lenis, Swiper, MapLibre, and Lottie. Before changing an animation, check for repeated initializations, already attached handlers, and state cleanup during transitions.
